\# Règle de validation



Avant toute action qui crée ou modifie un fichier, installe quelque chose ou lance une commande :

1\. Liste les actions prévues, numérotées : fichiers créés ou modifiés (chemin + rôle),

&#x20;  commandes exécutées, dépendances ajoutées.

2\. Explique en une phrase pourquoi chaque action est nécessaire.

3\. Arrête-toi et attends mon « ok ». Ne commence rien avant.



Après validation : exécute uniquement ce qui a été validé, puis résume le résultat

et propose l'étape suivante, sans l'enchaîner.



Autres règles :

\- Une étape à la fois, jamais de code au-delà de l'étape validée.

\- Vérifie les versions et les commandes dans la documentation officielle et cite la source.

&#x20; Si tu n'as pas pu vérifier, dis-le explicitement.

\- Applique le clean code et l'architecture hexagonale décrits dans le brief, avec les tests.

\- Réponds en français.
